# Plan: M5 — Process model Sequential + CLI maduro

> **Estado:** Implementado (2026-08-04). M5-base cierra el MVP. M5-ext.1/2
> ya estaban hechos; este plan cubre RF-38 (process model) y RF-40 (CLI
> maduro). ADR-0016. `paso.proto` no cambia (RNF-05).

## Decisiones de diseño (acordadas)

1. **El process model es un YAML envoltorio** (ADR-0016), no un modelo
   editable con callbacks (anti-patrón de TestStand, RF-N01). Reusa la
   maquinaria de sequence call de M4b (ADR-0010): el PM es la raíz y la
   secuencia del operador se inyecta como subsecuencia externa bajo
   `CLAVE_SECUENCIA_USUARIO` (`__anvil_usuario__`).
2. **`secuencia_usuario: true`** (campo nuevo en `DefinicionPaso`/`PasoYaml`)
   marca la invocación. El cargador lo reescribe a `secuencia: Some(CLAVE)`;
   el motor lo resuelve como cualquier subsecuencia externa. La frontera
   PM↔operador se comunica por `asigna`/`locals` (sin `parametros`,
   MVP-parcial).
3. **Composición en el cargador** (guest-side, ADR-0005): el host no
   inyecta el `Programa` en memoria; el CLI guest pasa `--process-model` al
   cargador, que compone. El host sólo recolecta `ejecutores:` de ambos
   para la relajación acotada del loopback (ADR-0011).
4. **CLI maduro** (RF-40): `--help`/`-h`, `--version`/`-V`, errores de parseo
   claros (lista de flags válidos), flags en cualquier posición (el
   posicional es la secuencia). `--solo-loopback` documentado.
5. **Paths `wasm` normalizados al cargar**: `TipoEjecutor::Wasm { path }`
   se guarda como clave canónica (relativa al YAML que lo declara); el host
   los usa tal cual. Con PM, los `.wasm` del PM son relativos a su
   directorio (no al de la secuencia usuario).
6. **Un UUT, sin loop** (MVP-parcial): el loop sobre UUTs es post-MVP
   (ligado a paralelismo, RF-39).

## Piezas (todas completadas)

1. **Modelo** (`crates/modelo/src/lib.rs`): campo `secuencia_usuario: bool`
   en `DefinicionPaso`; constante `CLAVE_SECUENCIA_USUARIO`.
2. **Cargador** (`crates/cargador/src/lib.rs`): `PasoYaml.secuencia_usuario`,
   inferencia de `tipo: sequence_call` cuando el flag está, validaciones
   (sin `secuencia`/`parametros`), `cargar_programa_con_process_model`
   (composición + merge de archivos/ejecutores + revalidación de ciclos),
   refactor `cargar_programa_resuelto`/`validar_programa`, `visitar`
   resuelve `secuencia_usuario` contra `CLAVE`, paths `wasm` normalizados.
3. **Motor** (`crates/motor/src/lib.rs`): `ejecuta_sequence_call` resuelve
   `secuencia_usuario` contra `programa.archivos[CLAVE]` (cambio mínimo).
4. **CLI guest** (`crates/motor/src/bin/anvil.rs`): `--process-model`,
   `--help`/`-h`, `--version`/`-V`, parseo de flags con salto de valores,
   errores claros con `USO`.
5. **Host** (`packaging/anvil-host/src/main.rs`): passthrough
   `--process-model`, primer posicional correcto (no confunde valores de
   flags), `.wasm` paths tal cual (normalizados).
6. **Ejemplo** `ejemplos/process_model_sequential.yaml`: PM mínimo
   reutilizable (identificar UUT → call `secuencia_usuario` → notificar).
7. **Docs**: ADR-0016, `proceso-de-test.md` (de "propuesta" a "hecho"),
   `roadmap.md` (M5 ✅), `requisitos.md` (RF-38/RF-40), `guia-inicio-rapido.md`,
   este plan.

## Verificación

- `cargo test` — 69 cargador (9 nuevos de PM) + 37 motor (2 nuevos) + resto:
  todo verde.
- `cargo build --target wasm32-wasip2 -p motor -p ejecutor_pasos` — guests
  compilan a WASI P2.
- `cargo build --manifest-path packaging/anvil-host/Cargo.toml` — host
  compila sin warnings.
- **Smoke**: `./anvil --process-model ejemplos/process_model_sequential.yaml
  ejemplos/basica.yaml --json out.json` → PM corre como raíz, identifica
  UUT, invoca `basica.yaml` como secuencia usuario, anida en `sub_pasos`,
  captura estado (`fallo`), JSON correcto, exit 0.
- **Smoke compat**: `./anvil ejemplos/basica.yaml` (sin PM) → sin cambios.
- **Smoke error**: PM sin invocar al usuario → "no invoca a la secuencia
  usuario"; sin `--process-model` con el flag → "no se corre con
  --process-model".
- `./anvil --help` y `./anvil --version` responden correctamente.
- `./anvil ejemplos/demo_wasm.yaml` (M5-ext.2) sigue funcionando (paths
  `wasm` normalizados).

## Recortes MVP-parcial (señalados, post-MVP)

- **Loop sobre UUTs** (ligado a paralelismo, RF-39).
- **Parallel/Batch** (post-MVP).
- **By-value / by-reference transitivo** en la frontera PM↔operador
  (heredado de ADR-0010).
- **Sidecar `--limits`** alcanzando a la secuencia usuario (heredado de
  ADR-0010: aplica a la raíz).
- **Identificación/notificación reales** (scanner, MES, luz): el PM de serie
  simula; los reales son pasos plug-in del usuario.
- Optimizaciones post-M5-ext.2 (AOT `.cwasm`, `StoreLimitsBuilder`, lazy
  loading, modo Debug, pooling/async, shutdown ordenado) — condicionadas
  a medición de 50+ Stores.
